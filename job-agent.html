Job Agent: Local AI Job Application Helper

Python · Ollama (local LLMs) · SQLite · pytest · November 2026 · Source on GitHub · Recorded demo

AI-written cover letters have a quality problem: they quietly invent experience by borrowing duties from the job description and attributing them to the applicant. I built this tool to treat that as a QA problem. It generates a letter, tests every claim in it against a source of truth (the resume), and removes whatever fails.

Everything runs on my own computer. The language models run locally on my GPU through Ollama, so no resume or job data is sent to a cloud AI service.

What it does

Resume parsing

Reads PDF, DOCX or text resumes into a structured profile, cached until the file changes.

Job ranking

Ranks saved job postings by how well they match the resume and the search ("QA tester" expands to related titles), flags roles above the applicant's experience level, and gives the best matches a 1–10 fit score listing matched requirements and gaps.

Fact-checked cover letters

Drafts a letter, checks each sentence about the applicant against the resume, revises, and deletes sentences that still fail. Banned clichés and length are enforced in plain code rather than trusted to the model.

Application tracker

A local SQLite log of every job scored or applied to, with fit, saved letter, status, dates and notes. It catches duplicate postings so the same job isn't applied to twice.

Testing it like a QA project

I tested the tool against my own resume and real job postings, and checked its output claim by claim. Those checks drove most of the design.

Defect found: invented experience

On a sample mobile QA posting, the first draft claimed experience that came from the job description, not the resume:

Draft“I also maintained test plans and collaborated with developers to reproduce issues…”
ResultThe fact-check flagged the sentence as unsupported and the revision removed it. On a real Windows endpoint QA posting, it likewise removed an unsupported claim of “experience in Windows environments, endpoint management.”

Fixes that came from testing

  • Revise-then-delete loop: sentences that still fail after two revisions are deleted instead of sent.
  • Code-enforced style rules: the model kept using banned openers like “I am writing to express my interest,” so they are now checked in code.
  • Seniority cap: the model suggested Senior and Architect titles for four years of experience, so levels are now capped in code.
  • Confirmed facts: real experience missing from the resume (like reproducing bugs) can be recorded, tied to a specific job, so the checker doesn't strip true claims.
  • Automated tests: 47 pytest tests cover these rules using a fake model, and I confirmed they catch bugs by breaking the code on purpose.

Known limitation

The fact-check still misses claims that blend two true facts into a false one, such as tying a tool listed only under Skills to a specific employer. A model more than twice the size caught no more of these and took over six minutes per check, so the planned fix is structural: split the resume into sections in code and check each claim against only its matching section.

How it was built

I built this with Claude Code as an AI pair programmer. I set the requirements (local-only, honest letters, review before sending), tested every stage against real data, and verified the output against my resume line by line. When a test failed, I fed that back as the next fix.
